# Trabajo imprevisto sin inflar el tablero

1. Determinar si el problema impide la entrega actual o es independiente. Buscar coincidencias **en Backlog.md**, no en roadmaps y archivos Markdown paralelos.
2. Corregir dentro del slice si es inseparable; proponer una tarea nativa con valor propio o borrador para una hipótesis.
3. Evitar tickets por cada warning, estimaciones inventadas, informes y gates. No interrumpir implementación por documentación de seguimiento ausente.
4. Para dependencias técnicas reales, activar [flow-recovery](flow-recovery.md) al primer bloqueo persistente: hipótesis, comprobación focalizada y decisión entre corrección en alcance, desbloqueante independiente o repriorización. Ejecutar el camino con menor coste real. Nunca falsear Done.
5. Continuar la tarea original cuando no hay bloqueo; no lanzar scans ni reconciliaciones globales por rutina.

**Salida:** corrección concreta o propuesta mínima en Backlog.md.
