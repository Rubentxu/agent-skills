# Work alignment — alinear código y tareas sin ceremonias

1. Al reanudar o concluir, comparar tarea Backlog.md con código/commits **cuando exista duda significativa**, no hacer reconciliación global tras cada edición.
2. Registrar progreso y archivos relevantes cuando beneficie al siguiente desarrollador. `--modified-file` reemplaza todo el conjunto: conservar entradas anteriores al modificarlo.
3. Trabajo no asociado: incluirlo en tarea activa si corresponde o proponer otra **solo** para valor independiente; no exigir enlaces administrativos.
4. Groma, C4 y hooks son optativos; ausencia de mapa, scanner o snapshot no impide desarrollar.
5. Verificar AC/DoD por comportamiento y evidencia real, no por sincronización documental o gates de seguimiento.

**Salida:** resultado y seguimiento nativo o un problema técnico concreto.
