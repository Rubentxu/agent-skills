# ADR-004 — Backlog.md conserva la autoridad operativa y de decisiones

**Estado:** aceptado para la skill (2026-11-01).

## Decisión
- Usar `backlog decision create/view/edit/list`, `--superseded-by`, comentarios y referencias de tareas para conservar decisiones y vínculos. Respetar estados libres de la instalación real.
- El origen de una decisión humana se referencia mediante identificadores privados (provider/session/message/date/digest) en el campo Context de la decisión Backlog, sin replicar transcripciones.
- Los proyectores de memoria, handoff, feedback y exportación son **funciones puras** sobre JSON de la CLI y snapshots de origen; no persisten otra tabla de decisiones, no editan Markdown de Backlog, no reemplazan Groma.
- Groma mantiene ownership de código, Backlog mantiene tareas y decisiones, Git acredita cambios, tests acreditan resultados bajo su revisión.
- Las opiniones/votos de agentes son propuestas de revisión; únicamente la persona puede aceptar/sustituir una política humana.

## Consecuencias
Se evita un nuevo servidor o índice de autoridad. Persistencia y sincronización siguen las garantías efectivas de Backlog: la política de documentos fuera de Git **requiere** backup y medio privado de sincronización antes de asumir continuidad entre equipos.
