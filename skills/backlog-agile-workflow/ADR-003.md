# ADR-003 — Provenance before authority

**Estado:** aceptado para la skill (2026-11-01).

## Contexto
Un resumen o handoff puede atribuir a la persona una decisión que solo infirió otro agente. Las referencias de tarea y un commit no autentican una aprobación.

## Decisión
- Distinguir **texto humano original**, interpretación, decisión nativa Backlog.md, evidencia de implementación y permisos de herramientas.
- Un pin de origen exige provider, sessionId, messageId, timestamp, digest de contenido y cita exacta. La cita ha de estar en el mensaje original consultado de forma independiente, con autor humano constatado; la aprobación explícita debe estar acreditada por el adaptador anfitrión.
- `authority_context.py` compara instantáneas y devuelve VERIFIED, UNVERIFIED, STALE o CONFLICTED. La validación **no autentica** un JSON arbitrario ni concede permisos; el host controla identidad y capacidades de herramientas.
- Un mensaje de agente, una respuesta de LLM y un evento UserPromptSubmit sin autor certificado nunca son aprobación humana.
- Un estado aceptado en Backlog.md acredita estado documental, **no** la procedencia por sí solo.
- En conflicto, falta de fuente o sustitución, fallar cerrado para la reclamación de autoridad; no detener operaciones de lectura inocuas.

## Consecuencias
Se crean pequeños contratos de intercambio que requieren snapshots obtenidos por adaptadores de confianza. Los datos privados (mensajes, citas) no se versionan en Git ni se incluyen en commits. El coste de recuperar la fuente existe solo cuando una autoridad está en duda.
