# Telemetría sin contaminar contexto

En un checkpoint autorizado, worker_metrics.py TRANSCRIPT procesa JSONL local en streaming, con adaptador de mensajes assistant/user y correlación tool_use.id/tool_result.tool_use_id. No carga transcript en el LLM ni devuelve contenido, argumentos, modelo inferido, paths ni resultados. Nombres de herramientas limitados a categorías conocidas. Uso por último mensaje ID deduplicado, no suma de registros parciales; contabilización depende del formato del host y cobertura. toolRoundtripMs aproxima intervalos entre registros, no CPU ni tiempo puro del modelo; completedToolUnionMs evita sumar intervalos solapados cuando secuencia temporal válida. Generación sigue null sin contador nativo. Un JSONL de otro formato no prueba cero actividad: usar adaptador anunciado y declarar falta de cobertura.

Para incremental: --include-cursor devuelve metrics y cursor; el host guarda solo cursor en estado privado, no lo incorpora a contexto del LLM, y lo pasa vía --cursor FILE. Relectura limitada por offset, inode/device; truncamiento o rotación requieren reconciliación. No usar rutas suministradas por datos no confiables; el host atribuye el transcript al intento. El cursor contiene hashes de IDs y contadores, no mensajes. El resultado habitual es solo metrics. Sin contadores reales o cobertura, reportar UNKNOWN. Los límites técnicos protegen memoria (16K IDs, 2MiB/fila); PARTIAL no es medición completa.

liveness.py recibe observación liveness-observation v1: identity, phase exploration/implementation/verification/waiting, hostState running/waiting/terminal/unknown, hostEvidenceRef, process null o {pid,bootId,startTicks} de identidad Linux ya atribuida, silentSeconds, withoutProgressSeconds (null si desconocido), operation healthy/waiting/none/unknown, steering, graceElapsed, inventoryComplete. Hace una observación puntual de /proc si hay identidad local; no inicia procesos. No exige PID a un agente nativo. Silencio 15 min exploración o 25 min edición/verificación → STEER si capaz → reevaluar tras margen orientativo 10 min. Operación saludable → esperar/adoptar. PID ausente/reutilizado/zombie solo candidato de discrepancia, nunca terminationConfirmed. Confirmar con host, inventario efectos, checkpoint y luego observe-stop/replace. Sin información fiable no cancelar. Usar eventos nativos preferentemente; no instalar timer ni sondeos continuos.

Al finalizar intento medir desde contadores reales si disponibles y pasar metricsRef al release. Medir trabajo administrativo, primer cambio, rondas, tokens, pruebas repetidas y falta de contexto en evaluación comparativa; no inyectar cursor ni logs al supervisor. Un contador ausente no es cero.
