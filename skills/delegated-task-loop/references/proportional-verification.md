Usar git status --porcelain, git log BASE..HEAD, git diff --name-status y git for-each-ref; consultar cada remoto autorizado con git ls-remote --refs (no usar solo origin/main cacheado). Atribuir ref al repositorio+remoto correcto, no incluir URLs con credenciales ni publicar snapshots. Si varios remotos, una entrada identificada por repo+remote y lista completa. Guardar snapshots privados. Antes de aceptar, obtener de nuevo observaciones. publication_audit.py recibe publication-audit-input v1 por stdin, repositories [{id,baseline:{local,remote},after:{local,remote},allowedLocalRefs,allowedRemoteRefs,evidenceRef}]. Los maps son ref→SHA completo, remote null si no disponible. Las excepciones son refs exactas autorizadas. Refs nuevas, borradas o cambiadas no autorizadas → INVESTIGATE; ausencia de evidencia remota UNKNOWN. No detectar pushes revertidos solo por snapshot; consultar eventos de proveedor cuando necesario. No afirmar autoría de cambios por coincidencia temporal; no hacer rollback/delete automático. Comprobar diff/path scope y worktree independientemente. Preferir permisos efectivos que impidan publicación.
