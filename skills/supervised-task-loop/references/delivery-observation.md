# Observación de entrega para el driver externo

El supervisor de proceso mide continuidad; no puede deducir aceptación técnica del estado del tablero. El verificador autorizado (humano, supervisor externo o adaptador de CI existente) contrasta fuentes originales, criterios, destino y comportamiento público. No es el worker. El operador proporciona la ruta absoluta a un JSON mediante AGENT_DELIVERY_OBSERVATION al medir o reanudar la misma iteración. No se descubre un fichero arbitrario del worker. El driver no ejecuta ni autentica el verificador: proteger la observación y la configuración con el host; con procesos del mismo UID no existe aislamiento de seguridad implícito.

Campos exactos: schemaVersion=1, kind=delivery-observation, taskId, sessionId (session.json), beforeDigest y afterDigest (SHA-256 del JSON canónico: claves ordenadas, UTF-8, ensure_ascii=False, separadores coma/dos puntos), scope (research/internal/integration/product-capability/release), targetRef (revisión o artefacto observado), reviewerRef (referencia al origen de la observación), definitionOfDoneCount (desde task view, incluso si list no lo proyecta), criteria (mapa AC:1… y DOD:1… usando los índices originales), target, consumer (obligatorio para product-capability/release; null si no aplica). Cada comprobación tiene status PASS/FAIL/BLOCKED/NOT_RUN y evidenceRefs (referencias no secretas a evidencia primaria; PASS/FAIL/BLOCKED no pueden carecer de ellas).

El verificador comprueba que el alcance es el autorizado antes de delegar, no uno reducido para cerrar. Usa los mismos criterios y revisiones en las evidencias; verifica CI, Git, producto o documentación según el destino. No crear pruebas nuevas si existe evidencia vigente. Si hay una enmienda aprobada que cambia el número de AC, reconciliar la baseline explícitamente, nunca editar snapshots históricos.

El informe solo valida coherencia de campos, identidad, snapshots, contadores y cobertura de resultados. NO verifica autenticidad de referencias ni otorga permisos. Sin observación se produce NOT_RUN y el bucle se detiene; el operador puede aportar la observación y reanudar la misma iteración sin repetir implementación. Un PASS antiguo (esquema 1) no acredita entrega. El reporte almacena el digest, no las referencias privadas. El estado del tablero sigue siendo de Backlog.md: si se cerró indebidamente, corregir por su CLI autorizada tras inspección; no reabrir ni publicar automáticamente.

Esta transición deliberadamente requiere un productor de observaciones autorizado en los despliegues desatendidos; hasta integrarlo no se afirma aceptación automática.
