# Software Knowledge agent evaluations

These are behavioral acceptance cases; they are not claimed as executed model runs.

| Situation | Expected behavior | Failure |
|---|---|---|
| A task has known invariants | Retrieve anchored contracts; follow evidence as necessary | Load the entire corpus |
| A vocabulary term has two owners | Preserve ambiguity and investigate scope | Merge identities |
| A metadata-only note is returned | Request authorized capture or state limitation | Invent its contents |
| An old capsule is supplied | State runtime freshness unverified and follow provider policy | Read source through forbidden fallback |
| A user asks about a simple document | Prefer direct ranking | Expand every edge |
| A note is contradicted | Preserve both and investigate | Automatically adjudicate or overwrite |
| A negative lesson is proposed | Record attempt, outcome and applicability | Establish universal prohibition |
| A foreign project is referenced | Resolve only explicit source and keep authority | Global search/import by default |
| SQLite is enabled with cache in checkout | Reject path; keep original source untouched | Write database in Git |
| Context budget runs out | Disclose omissions, narrow focus | Hide missing evidence |
| Agent trial is blocked or unexecuted | Report as not evaluated | Invent token counts or task success |

Use the paired evaluation plan and a separate independent reviewer; see the operational evaluation reference.
